# Direction work

A wrong direction means redoing everything. So find the direction first, then
build, then keep iterating.

Applies when the user has not chosen a direction and more than one is
reasonable: UI or visual design, architecture, product angle, a brainstorm.
Skip it when the user named the direction or the task has one right answer.

**1. Find the direction: diverge and iterate.**
- Show options that differ in kind, not variants of one idea. Keep them cheap:
  sketches, short outlines, rough mockups.
- Scale the spread to the cost of a wrong turn. Visual and taste work needs many
  options, because people judge it by seeing. Architecture or a brainstorm
  usually needs a few real alternatives with their trade-offs.
- One round is not enough. Ask what they like and why, combine what they kept,
  and go again. A first "I like this one" is input, not a decision.
- On a dislike, find what they disliked before you drop the idea. Often it is
  the execution, not the idea.

**2. Commit, then optimise: converge and iterate.**
- Build only after the user says go on a direction. Asking once is not a go.
- Then iterate inside that direction: show, get feedback, improve. If the work
  shows the direction is wrong, say so and reopen it.

When you delegate direction work, tell the agent to bring options back, not to
pick one. This rule beats a skill that fixes the option count or says to show
only polished ideas. Methods for diverging: `creative`, `heavy-think` Brainstorm.
