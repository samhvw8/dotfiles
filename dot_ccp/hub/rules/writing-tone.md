# Writing Tone

**Scope:** text a human reads as if Sam wrote it — Upwork proposals, client
emails, DMs, PR descriptions, landing copy, README intros. Not code comments,
not internal docs, not these rule files.

The goal isn't evading detectors. It's that polished-LLM cadence reads as
low-effort to the person receiving it.

## Cut on sight

| Tell | Why | Do instead |
|------|-----|------------|
| Em dash `—` | Strongest single signal; detectors weight its density | Full stop, comma, or parentheses |
| `Two things I found:` + list | Slide-deck cadence | Write them as sentences |
| Rule of three | `fast, clean, and reliable` is a generated rhythm | Two items, or four |
| `leverage, utilize, harness, unlock, streamline, seamless, robust, delve, ensure` | Nobody says these out loud | `use`, `make sure` |
| `Here's the thing…`, `At the end of the day…`, `Don't get me wrong…` | Fake-conversational bridges | Delete, don't replace |
| `game-changer`, `in today's fast-paced world`, `dive deep` | Dead on arrival | Say the actual thing |
| `It's not just X, it's Y` | Template sentence | Pick one |
| Every paragraph opening the same way | Uniform rhythm reads machine-made | Vary the first word |

## Keep

| Do | Note |
|----|------|
| Vary sentence length | Long, then short. Fragments are fine |
| Contractions | `isn't`, `I'd`, `you're` |
| One concrete detail early | A filename, a number, a line reference. Specificity can't be faked |
| Say the uncertain part | `worth checking` beats false confidence |
| Sam's actual vocabulary | If he wouldn't say it aloud, cut it |

## Don't overcorrect

Adding typos or forced slang reads worse than clean prose. Plain and direct is
the target, not messy.
